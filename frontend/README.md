# Frontend - Marellis Recipe Website

Modern, responsive recipe browser built with vanilla JavaScript, HTML5, and CSS3.

## Features

- 📱 Responsive design for mobile, tablet, and desktop
- 🔍 Full-text search across recipes, ingredients, and descriptions
- 📂 Browse recipes by category
- ➕ Add, edit, and delete recipes
- 🔗 Support for external links and recipe references
- 🎨 Clean, modern Material Design-inspired interface
- ⚡ Fast, lightweight (no external frameworks)
- 🔐 CORS-enabled for API consumption from GitHub Pages

## Architecture

### File Structure

```
frontend/
├── index.html    # Main HTML structure
├── app.js        # Application logic and interactivity
├── api.js        # Backend API client
├── style.css     # Styling and responsive design
└── README.md     # This file
```

### Component Design

The application uses a component-based architecture:

1. **app.js** - Main application controller
   - State management
   - Event handling
   - DOM manipulation
   - Local storage integration (migrating to backend API)

2. **api.js** - Backend API client
   - Abstraction layer for backend communication
   - Environment-aware URL configuration (dev/prod)
   - Error handling
   - Promise-based async interface

3. **index.html** - UI structure
   - Semantic HTML
   - SVG icon sprite (no external font dependencies)
   - Accessibility features (ARIA labels)
   - Modal dialogs for forms

4. **style.css** - Responsive styling
   - Mobile-first approach
   - CSS Grid for layouts
   - CSS custom properties for theming
   - No external CSS frameworks

## Data Model

```javascript
Recipe {
  id: number,              // Auto-generated by backend
  title: string,           // Recipe name
  description: string,     // Short description
  categories: string[],    // e.g., ["breakfast", "vegetarian"]
  ingredients: string[],   // List of ingredients
  steps: string[],         // Cooking instructions
  links: {                 // Optional references
    type: "external" | "recipe",
    url?: string,          // For external links
    label?: string,        // Display text
    linked_recipe_id?: number  // For recipe links
  }[],
  created_at: timestamp,
  updated_at: timestamp
}
```

## API Integration

The frontend communicates with the backend via the `api.js` client:

```javascript
// Get all recipes
const recipes = await API.recipes.getAll();

// Filter by category
const breakfast = await API.recipes.getAll({ category: 'breakfast' });

// Search
const results = await API.recipes.getAll({ q: 'pancake' });

// CRUD operations
const recipe = await API.recipes.create(recipeData);
const updated = await API.recipes.update(id, recipeData);
await API.recipes.delete(id);

// Get categories
const categories = await API.categories.getAll();
```

## Configuration

### API URLs

Edit `api.js` to configure API endpoints:

```javascript
const API_CONFIG = {
  development: 'http://localhost:8080',
  production: 'https://your-app.fly.dev', // Update with production URL
};
```

The frontend automatically detects the environment:
- **Development**: Running on `localhost` or file://
- **Production**: Running on GitHub Pages domain

## Development

### Quick Start

```bash
# Start a local web server
python -m http.server 8000

# Or use any other server
npx http-server
cd-server
node server.js
```

Open `http://localhost:8000` in your browser.

### Making Changes

1. Edit `index.html`, `app.js`, `style.css`, or `api.js`
2. Save the file
3. Refresh the browser (F5 or Ctrl+R)

No build step required - changes are immediate!

### Testing

1. Run the frontend locally with a web server
2. Start the backend API (`cd backend && go run cmd/api/main.go`)
3. Test CRUD operations through the UI:
   - Create recipes
   - Search and filter
   - Edit recipes
   - Delete recipes

## Deployment

### GitHub Pages

1. Push the `frontend/` folder contents to your repository
2. Enable GitHub Pages in repository settings
3. Configure production API URL in `api.js`

**Note**: Frontend is now configured to be deployed from the `frontend/` folder. If using GitHub Pages with a custom domain or repository subfolder deployment:

Edit `api.js`:
```javascript
production: 'https://your-custom-domain/api', // or https://your-app.fly.dev
```

## Maintenance

### Common Tasks

**Clear all data**: 
- For localStorage version: Open DevTools → Application → Clear Storage
- For API version: Delete recipes through UI or API

**Reset to seed data**:
- Delete the SQLite database in backend
- Restart backend (will recreate schema)

**Update API URL**:
- Edit `frontend/api.js` → `API_CONFIG.production`
- Rebuild and redeploy if needed

## Troubleshooting

### API Connection Issues
1. Check browser console (F12) for CORS errors
2. Verify backend is running on correct port
3. Check `api.js` configuration
4. Ensure CORS_ORIGIN in backend `.env` includes your frontend domain

### Recipe Not Saving
1. Check network tab in DevTools for failed requests
2. Verify backend API is responding
3. Check browser console for JavaScript errors
4. Look at backend logs for server errors

### Styling Issues
1. Hard refresh browser (Ctrl+Shift+R or Cmd+Shift+R)
2. Clear browser cache
3. Check CSS file is being loaded (DevTools Network tab)
